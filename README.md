# 水の中

**体験できるURL：https://katomi95.github.io/mizu-no-naka/**（Meta Quest 3 のブラウザで開いてください。PCではプレビューモードで見られます）

Meta Quest 3 のブラウザで見る、パススルーMRの短い作品です。
現実の自分の部屋が、だんだん水の中になります。魚が泳ぎ、水草が揺れ、泡が上り、頭の上には水面が揺れています。
スコアも勝ち負けも時間制限もありません。ただ眺めるだけです。

- WebXR Device API（`immersive-ar` セッション）+ Three.js r165
- HTML / CSS / JavaScript だけで動きます。ビルドもサーバー処理もありません
- Three.js は `vendor/` に同梱しています（CDNには依存しません）
- 魚・水草・水面などは全部プログラムで作っています（3Dモデルや画像のファイルはありません）
- 音は WebAudio で合成しています（音声ファイルはありません）

## 体験の流れ

1. タイトル画面で「はじめる」を押すと、パススルーで現実の部屋が見えます
2. 数秒〜十数秒かけて、少しずつ水の中になります
   - 1秒ごろ：床から小さな泡が上り始める
   - 2秒ごろ：部屋全体がうっすら青緑色になっていく
   - 3〜5秒ごろ：細かい粒が漂い、頭上に水面が現れ、光の筋が差し込み、床に光の模様が揺れる
   - 6秒ごろ：遠くから小魚が泳いでくる（だんだん近くに来て、まわりを回り始める）
   - 8秒ごろ：足元のまわりに水草が伸びて、揺れ始める
3. あとは何も起きず、水の中のまま続きます
4. 30〜45秒ごろに一度だけ、大きな魚が遠くから現れて、まわりをゆっくり横切って去っていきます（説明は出ません）

## 操作

| | Quest 3 | PCプレビュー |
|---|---|---|
| 開始 | 「はじめる」 | 「PCプレビュー」 |
| 見回す | 頭を動かす | マウスでドラッグ |
| 終わる | 足元の「おわる」をコントローラーで指してトリガー。または Meta ボタン → 終了 | 左上の「おわる」（3D空間の「おわる」をクリックしても終わります） |

それ以外の操作はありません。移動もしなくていいので、座ったままで大丈夫です。

「おわる」ボタンは、はじめたときの正面の少し下（見下ろすと見えるくらい、目から約0.5m先）に置かれます。頭について来ません。コントローラーでボタンの近くを指したときだけ、細い光線が出ます。

## Quest 3 での起動方法

WebXR は **HTTPS** でしか動きません（`localhost` だけは例外です）。

### A. GitHub Pages で開く（おすすめ）

1. このフォルダ（`index.html` があるところ）をリポジトリのルートにして push します
2. GitHub のリポジトリで Settings → Pages → Source を「Deploy from a branch」、Branch を `main` / `/(root)` にします
3. 少し待つと `https://<ユーザー名>.github.io/<リポジトリ名>/` で開けるようになります
4. Quest 3 の **Meta Quest ブラウザ** でこのURLを開き、「はじめる」を押します
5. 許可のダイアログが出たら許可します。現実の部屋が見えたら開始です
   - 「空間データ（部屋の情報）へのアクセス」の許可を求められることがあります。これは壁や天井に光の模様を映すための**任意の機能**です。拒否しても、それ以外はすべて同じように動きます

### B. PC のローカルサーバーを USB 経由で Quest から開く（開発用）

1. PC でこのフォルダを配信します（`.js` を `text/javascript` で返すサーバーを使ってください。下の注意を参照）
   ```bash
   npx http-server -p 8000 -c-1
   ```
2. Quest を USB でつなぎ（開発者モードと adb が必要です）、ポートを転送します
   ```bash
   adb reverse tcp:8000 tcp:8000
   ```
3. Quest のブラウザで `http://localhost:8000/` を開きます（`localhost` は安全なコンテキスト扱いなので WebXR が使えます）

PCのIPアドレス（`http://192.168.x.x:8000`）で開くと HTTPS ではないので WebXR は使えません。タイトル画面にその理由が表示されます。

> 注意：Windows の `python -m http.server` は、レジストリの設定によっては `.js` を `text/plain` で返します。そうなると ES モジュールが読み込めず、画面が真っ暗になります。そのときは `npx http-server` などを使ってください。

## PCプレビュー

開発・確認用です。パススルーの代わりに、床・壁・天井と家具だけの簡単な部屋を表示します。

1. 上と同じようにローカルサーバーで配信して、PCのブラウザ（Chrome / Edge / Firefox）で `http://localhost:8000/` を開きます
   - `index.html` をダブルクリックして `file://` で開いても動きません（ES モジュールの制約です）
2. 「PCプレビュー」を押します
3. マウスでドラッグすると見回せます。カメラは座った人の目の高さ（1.2m）に固定です

水中の演出（`js/world.js` 以下）は Quest 版とまったく同じものを使っています。違うのは背景（仮想の部屋かパススルーか）と視点の動かし方だけです。
仮想の部屋は深度を書かずに一番最初に描いているので、XR と同じく **CG はいつも部屋の手前に重なります**（壁の向こうへ泳いでいく魚も見えます）。

### 確認用の URL パラメータ

| パラメータ | 内容 |
|---|---|
| `?t=30` | 開始から30秒たったところから始めます（大きな魚は 32〜42秒の間のどこかで現れます。`?t=31` で始めればすぐ見られます） |
| `?planes=0` | 平面検出（壁・天井の光の模様）を要求しません。Quest で部屋の情報の許可を出したくないとき用 |

ブラウザのコンソールで `window.__mizu` からカメラや世界の状態を触れます（例：`__mizu.lookAtPoint(x, y, z)`、`__mizu.world.t`）。

## しくみと、WebXR でできないこと

### パススルーそのものには効果をかけられない

WebXR では、現実の部屋の映像（パススルー）はブラウザの外で合成されます。ページからは映像を読むことも、歪ませることも、フォグやポストエフェクトをかけることもできません。
そこで、水中らしさはすべて **空間に置いた半透明のCG** で作っています。

- **色かぶり**：頭を包む大きな球の内側に、ごく薄い青緑を塗っています（上は明るい水色、下は深い青緑）。CGより先に描くので、現実の部屋だけが水の色に沈み、魚の色は鮮やかなまま見えます。位置だけ頭に合わせ、向きは固定、明るさも時間で変えません
- **フォグ**：Three.js のフォグは CG にだけかかります。遠くの魚ほどかすみ、さらに 3.6〜5.4m（大きな魚は 4.4〜6.6m）で透明になって水に溶けるように消えます
- **水面**：頭上 1.6m に水平な円盤を置き、コースティクス模様（起動時にセルノイズから計算した網目模様）を2層、別の向きにゆっくり流しています。真上あたり（約48°以内）が明るく、斜めに見るほど深い色になります（水中から水面を見上げたときの「スネルの窓」のつもりです）。現実の天井の高さとは合わせていません
- **光の筋・微粒子・気泡**：どれも空間に固定したCGです

### 酔いへの配慮

- 視点を動かすのは本人の頭の動きだけです。カメラを揺らす、視点を勝手に動かす、画面全体を点滅させる、視界全体を歪ませる、といったことはしていません
- 頭について来るものは色かぶりの球だけで、これは向きを持たない一様な色なので、頭を動かしても何も動いて見えません
- 動くのは魚・水草・泡・水面の模様などのCGだけで、どれもゆっくりです。演出は数秒かけてフェードインします
- 魚は自分のまわり 0.9m より内側には来ません。泡も顔の真下からは出ません。目の前 0.2〜0.5m に来た粒は薄くして消します

### 現実の壁・天井への光の模様（平面検出）

WebXR の `plane-detection` を「使えたら使う」機能として要求しています。Quest で部屋のスキャン（空間設定）が済んでいて、許可が出た場合だけ、検出された壁・天井・机などの面に、水面からの光のような模様をうっすら重ねます（上の方ほど明るく）。
許可しない、スキャンがない、対応していない、のどれでも、ほかの演出は同じように動きます。床は仮想の円盤に模様を出しているので、検出された床は使いません。

### そのほかの制約

- 床の高さは `local-floor` 基準空間で取っています。使えないときは `local` にして、目の高さを1.3mと仮定します（座っていると床が少し下にずれます）
- 世界の向きと位置は、はじめた瞬間の頭の位置・向きを基準に決めます。その後に立ち上がったり歩いたりしても、水面や水草は部屋に固定されたままです
- CG はいつも現実の物の手前に描かれます（現実の家具の後ろに魚が隠れることはありません）。家具とのぶつかりも考えていません
- 水面の高さは「はじめたときの目の高さ + 1.6m」です。立ってはじめると現実の天井より上になりますが、見上げると天井に重なって見えます
- ハンドトラッキングは要求していません。手で「おわる」を押せるかは未確認です（Meta ボタンからはいつでも終われます）

## 負荷

- 描画は約20回（ドローコール）、三角形は約4,300枚（PCプレビューで計測）
- 魚は1匹1メッシュ（小魚9匹＋大きな魚1匹）。水草は全部で1メッシュ、泡（最大110個）と微粒子（140個）はそれぞれインスタンス描画1回
- ライトは環境光（半球光）と平行光の2つだけ。影なし、物理演算なし
- 画面全体に重なる半透明は、色かぶりの球1枚と、見上げたときの水面1枚だけです
- 毎フレーム新しいオブジェクトを作らないようにしています（泡の配列は使い回し）

## 実機での確認手順（未検証）

**この版は Quest 3 の実機ではまだ確認していません。** PCのブラウザでプレビューモードの表示と動き（演出の順番、魚・泡・水草・水面、大きな魚、「おわる」）と、パススルー用の透明度の出力（背景を透明にして描画したときのアルファ値）、平面検出の処理（模擬データ）を確認しただけです。実機で次を確認してください。

1. [ ] タイトル画面に「パススルーMRで体験できます」と出て、「はじめる」が押せる
2. [ ] 「はじめる」で現実の部屋が見える（真っ黒・真っ白にならない）
3. [ ] 最初の1秒ほどは普通の部屋で、そこから泡→色→水面→魚→水草の順に、急に切り替わらずに現れる
4. [ ] 部屋全体のうっすらした青緑が「水の中」に見える。濃すぎて部屋が見にくくなっていない（濃さは `js/water.js` の `WaterTint` の `mix(0.4, 0.22, …)`）
5. [ ] 見上げると水面が揺らめいて見える。まぶしすぎない・ちらつかない
6. [ ] 魚が「魚」に見える大きさと形で、尾を振りながらゆっくり泳ぎ、まわりを巡っている。瞬間移動やカクッとした方向転換がない
7. [ ] 遠くの魚がかすみ、さらに遠くでは消えていく（壁の手前に急に現れたり消えたりしない）
8. [ ] 水草が足元のまわりの**床の上**に生えている（浮いていない・埋まっていない）。揺れが穏やか
9. [ ] 泡が床から上って、上の方で消える。顔にぶつかってこない
10. [ ] 30〜45秒ごろ、大きな魚が遠くから現れ、ゆっくり横切って去る。一度だけ。メッセージは出ない
11. [ ] 部屋の情報の許可を出した場合、壁や天井にうっすら光の模様が揺れる（出なくても不具合ではありません）
12. [ ] 見下ろすと「おわる」がある。コントローラーで指すと光線が出てボタンが明るくなり、トリガーでタイトルに戻る。もう一度「はじめる」を押せる
13. [ ] Meta ボタン → 終了 でもタイトルに戻る
14. [ ] 環境音（低いこもった音と、ときどき小さな泡の音）が鳴る。大きすぎない
15. [ ] フレームレートが落ちていない（カクつきがない）。数分眺めても酔わない

うまく動かないとき：

- Quest を USB でつないで、PC の Chrome で `chrome://inspect/#devices` を開くと、Quest のブラウザのコンソールが見られます
- 床の高さがずれるときは、`local-floor` が使えているか確認してください（ガーディアン／境界の床の設定に影響されます）
- 許可ダイアログが気になるときは `?planes=0` を付けて開いてください
